NALAZI

F01 — P1 — R — Pohranjeni XSS u administraciji
Lokacije: admin.js:680, 712, 745, 849, 989, 1104; api.php:889, 933; .htaccess:40.
CMS ubacuje putanje, dio naslova i rich HTML neposredno u innerHTML. Serverska validacija putanje dopušta navodnike, a regex za rich HTML se može zaobići. U izolovanom API-ju prihvaćena je slika s vrijednošću x" onerror="window.__auditXss=2 i opis <img src=x /onerror="window.__auditRich=1">. Nakon ponovnog učitavanja i otvaranja editora oba bezopasna markera su postavljena u browseru.
Uticaj: sadržaj može izvršavati radnje u aktivnoj admin sesiji, čitati podatke dostupne adminu ili mijenjati CMS. Potreban je unos kroz ovlašteni CMS/API ili uvoz zlonamjernog backupa; nije potvrđen anonimni put od javnog korisnika do ovog polja. CSP unsafe-inline ne blokira takve handlere.
Ispravka: običan tekst postavljati preko textContent; slike/linkove stvarati DOM metodama i validirati URL; rich HTML sanitizirati allowlist parserom i u editoru i na serveru. Ukloniti inline skripte/handlere i uvesti strožiji CSP nakon prilagodbe frontend koda. Regresija mora pokriti naslov, putanju, galeriju, manual, blog i HTML opis.

F02 — P1 — R — Restore može staru sesiju povezati s drugim korisnikom
Lokacije: api.php:1682, 1709, 2191, 2216.
Sesija se potvrđuje preko user ID-a, role i auth_version. Restore zamjenjuje tabelu users i vraća auth_version iz backupa, bez globalnog poništavanja sesija.
Dokaz: prijava korisnika A sa ID-em X i auth_version=0; restore backupa u kojem ID X pripada korisniku B s drugom lozinkom i istim auth_version; stara sesija A prolazi customer_session_active i dobija ime B. Isti mehanizam se koristi za admin sesije. Vraćanje starijeg auth_version može oživjeti ranije opozvanu sesiju.
Ispravka: globalni nasumični auth epoch izvan obnovljivog backupa ili sigurno poništavanje svih postojećih sesija pri restoreu; ponovno prijavljivanje nakon restorea. Samo povećavanje vraćene verzije za 1 nije dovoljno jer može pogoditi neku postojeću sesiju.

F03 — P1 — R — Restore javlja grešku nakon već izvršenog brisanja i commita
Lokacije: api.php:2146, 2191, 2224, 2232.
Validacija backupa prihvata praznu users tabelu i ne potvrđuje prisustvo upotrebljivog admina, verziju formata ili integritet svih redova. seed_database se poziva poslije commita.
Dokaz: validan CMS backup bez korisnika, produkcijski režim i prazna početna admin lozinka. Restore baca izuzetak, ali izmijenjen CMS ostaje sačuvan i users tabela je prazna. Izuzetak ne može vratiti već potvrđenu transakciju. Postoji pre-restore fajl, ali aplikacija ostaje u neispravnom stanju i prijava može biti blokirana.
Ispravka: potpuna validacija šeme, tipova, verzije, referenci i admin identiteta prije izmjena; sve obavezne korake završiti u jednoj transakciji. Backupe v1/v2 migrirati eksplicitno. Ne prikazivati neuspjeh kao da stanje nije promijenjeno ako se ne može garantovati rollback.

F09 — P2 — R — Parser cijene mijenja vrijednost validnog broja
Lokacije: api.php:949, 1813; admin.js:273, 351; app.js:189; cart.js:32.
Validacija prihvata is_numeric zapis, a dalja obrada briše sve osim cifara i tačke. Zapis 1e3 zato postaje 13, iako broj znači 1000. Frontend parser briše i znak minus umjesto da odbije negativan unos.
Dokaz: mpcPrice='1e3' prolazi cms_validate_payload bez greške; product_price_label vraća '13'.
Ispravka: definisati jedan strogi decimalni format; odbiti eksponente, višestruke separatore i negativne cijene ili ih ispravno parsirati. Pohraniti iznos u najmanjoj novčanoj jedinici, uz jasno pravilo preciznosti; frontend i server moraju dati isti rezultat.

F10 — P2 — R — Akcija ističe različito u korpi i na proizvodu
Lokacije: cart.js:47; app.js:210; product.js:252; profile.js:84; api.php:1833.
Korpa koristi new Date('YYYY-MM-DD'), koji predstavlja UTC ponoć, pa naknadno postavlja lokalno vrijeme. Ostale stranice dodaju lokalni T23:59:59, a PHP koristi serversku vremensku zonu.
Dokaz: 04.10.2026. u America/Los_Angeles za saleUntil='2026-10-04' korpa kaže false, detalj proizvoda true. Korisnik vidi različite aktivne cijene. Server i Bosna mogu se dodatno razlikovati oko ponoći ako server radi u UTC.
Ispravka: poslovnu zonu eksplicitno odrediti kao Europe/Sarajevo, računati efektivnu cijenu na serveru i vratiti je svim prikazima. Ne oslanjati odluku o akciji na korisnikov sat ili lokalnu zonu.

F11 — P2 — R — Validacija referenci i javni prikaz koriste različita poređenja
Lokacije: api.php:876, 796–805, 1142–1180, 841–849.

Dokaz: kategorija proizvoda izmijenjena u velika slova; payload prolazi bez greške, a proizvod nestaje iz javnog CMS-a. Sličan nesklad postoji za veze manuala i proizvod/kategoriju.
Ispravka: koristiti stabilne categoryId i productId reference sa jednim pravilom normalizacije, ili odbiti nekanonski zapis. Validacija i prikaz moraju dijeliti isto pravilo.

F12 — P2 — K/R — JSON objekat može proći kao CMS lista i pokvariti editor
Lokacije: api.php:991; admin.js:535, 538, 1180, 1452.
PHP is_array ne razlikuje očekivanu listu od JSON objekta sa string ključevima. Kolekcija products={'key0':...} prolazi validaciju. Sačuvani puni CMS vraća objekat, a editor očekuje JS Array i poziva forEach/find/map.
Dokaz validacije: imenovani ključevi proizvoda prihvaćeni bez greške. Posljedica za editor potvrđena je njegovim pozivima array metoda; ovaj slučaj nije trajno upisan u glavni browser fixture.
Ispravka: provjeriti list strukturu i indekse na svakoj kolekciji i ugniježđenim listama; po potrebi eksplicitno normalizovati array_values prije pohrane. Za object mape koristiti odvojenu validaciju.

F13 — P2 — K — Izmjena i brisanje referenciranih entiteta nisu cjeloviti
Lokacije: admin.js:1221, 1231–1234, 1587, 1785; api.php:1174, 1230.

Posljedica: validator blokira spremanje cijelog CMS-a kada ostanu reference manuala/badgea/kategorije; bez takve reference stari favoriti i korpe mogu postati „Nedostupan proizvod“. Nema transakcijske migracije referenci.
Ispravka: tehničke ID-eve učiniti nepromjenjivim; uređivati poseban slug/naziv. Za brisanje ponuditi premještanje ili jasno uklanjanje zavisnosti. Sve reference ažurirati zajedno na serveru.

Dokaz: blokiran admin-orders zahtjev; rezultat ordersLoaded=true i orderCount=0.
Ispravka: koristiti zasebna loading/error/empty stanja, zadržati zadnje poznate podatke označene kao zastarjele i prikazati retry. Ne dozvoliti uređivanje kao da je početno učitavanje uspjelo. Početni cmsRevision=0 trenutačno blokira save, što ublažava prepisivanje demo sadržajem, ali ne ispravlja pogrešan prikaz.

F16 — P2 — R — Blokiran localStorage ruši inicijalizaciju stranice

Lokacije: api.php:619–699, 2029, 2054, 2076, 2240.
database poziva CREATE TABLE IF NOT EXISTS i provjere/migracije pri svakom zahtjevu, čak i za csrf-token i javni cms. orders/customers endpointi čitaju kompletnu historiju; paginacija u admin.js skraćuje samo prikaz nakon preuzimanja svega.
Uticaj: nepotrebni upiti i DDL prava web korisnika baze, rast latencije/memorije s brojem kupaca i upita; sporija mobilna mreža to jače osjeti. Nije proveden produkcijski load test niti je dokazan trenutni pad zbog opterećenja.
Ispravka: migracije pokretati odvojeno pri deployu; web DB nalogu dati samo potrebna runtime prava. Uvesti serversku paginaciju i filtere, agregate za brojače i odgovarajuće indekse. Ne zamijeniti zaštitu no-store za privatne podatke javnim keširanjem.

F25 — P2 — U/K — Operacije nad korpom nisu potpuno usklađene za više uređaja
Lokacije: api.php:1769–1800, 1921, 2601–2676.
Zatvaranje korpe ima zaključavanje i sprečava duplo slanje iste korpe, ali add/update/remove ne zaključavaju i ne provjeravaju isti red korpe pod istim protokolom. Nema ograničenja „jedna aktivna korpa po korisniku“.
Mogući raspored: sesija s telefona pročita aktivnu korpu; sesija s desktopa je pošalje; prva sesija upiše stavku u sada submitted korpu, pa njen uspješni odgovor prikazuje novu praznu korpu. Dvije sesije također mogu istovremeno kreirati aktivne korpe. PHP zaključavanje iste sesije ne štiti dva različita uređaja.
Status: rizik utvrđen pregledom transakcija i šeme, nije reproduciran pod konkurentnim MySQL opterećenjem jer testni runtime koristi SQLite i jednonitni PHP server.
Ispravka: sve mutacije prvo zaključavaju isti parent cart/user red, nakon toga provjeravaju status i verziju; uvesti DB invariant jedne aktivne korpe i konflikt 409 za zastarjelu verziju. Obavezno testirati paralelne stvarne MySQL konekcije.

F26 — P2 — U/K — Backup nema jedinstven konzistentan snapshot svih tabela
Lokacije: api.php:2117, 2122, 2210, 2791.
backup_payload radi više SELECT * poziva bez zajedničke read transakcije. Druga sesija može registrovati korisnika ili poslati upit između čitanja users, carts, cart_items i orders. Pre-restore backup koristi isti pristup.
Posljedica: backup može sadržavati kombinaciju različitih trenutaka, npr. referencu na korisnika koji nije u njegovoj users tabeli. MySQL šema dodatno nema iste strane ključeve kao SQLite. Nije izazivano produkcijsko preplitanje zahtjeva.
Ispravka: konzistentna read transakcija/snapshot za backup i provjera referencijalnog integriteta pri uvozu. Medije i dalje posebno kopirati jer JSON backup ne sadrži sadržaj uploadova; to je već ispravno dokumentovano.

F27 — P2 — K — Limit pokušaja prijave se može raspodijeliti po IP adresama
Lokacije: api.php:326, 2295–2313, 2535–2553, 302–324.
Admin limit je IP+admin; kupac ima IP i IP+email. Ne postoji brojilo po računu nezavisno od IP-a. Svaki novi izvor IP-a dobija nove pokušaje za isti račun. Provjera limita i upis pokušaja također nisu jedna atomska rezervacija.
Uticaj: ograničenje djeluje protiv jednostavnog napada s jedne adrese, ali samo po sebi ne pokriva distribuirano pogađanje lozinke. Cloudflare može imati dodatna pravila, koja nisu poznata iz repozitorija.
Ispravka: slojeviti limiti po nalogu, IP-u i sistemu uz progresivno usporavanje; bez jednostavne trajne blokade koju napadač može iskoristiti da zaključa žrtvu. Za admina uvesti MFA/passkey i sigurnosne događaje. Višefaktorska zaštita je preporučeno poboljšanje, njeno odsustvo samo po sebi nije dokaz preuzimanja računa.

F28 — P1 ako uslov postoji — U/K — Već postojeći admin s demo lozinkom nije blokiran u produkciji
Lokacije: api.php:702–736, 2279–2287, 2294–2316.
Pravilo jake početne lozinke primjenjuje se samo kada admin ne postoji. Ako se migrira baza/backup s poznatom lokalnom lozinkom onesadmin, prijava je i dalje dozvoljena. admin-status daje passwordNeedsChange upozorenje, ali backend ne ograničava upravljanje dok se lozinka ne promijeni.
Status: nije pokušavana produkcijska prijava tom lozinkom i nije utvrđeno da je produkcija koristi.
Ispravka: produkcijska provjera poznatih demo vjerodajnica i obavezna promjena prije pristupa ostalim admin radnjama; deployment/import mora odbiti nesigurnu početnu konfiguraciju. Ne resetovati postojeću lozinku pri običnom deployu.

F29 — P2 za lokalni razvoj; P1 ako isto vrijedi na serveru — R/U — Zastarjeli PHP runtime i zastarjeli minimum u dokumentaciji
Lokacija: lokalni php -v; DEPLOYMENT.md odjeljak Server requirements.
Lokalni runtime je PHP 7.4.27. Dokumentacija navodi PHP 8.1 ili noviji. U oktobru 2026. ni 7.4 ni 8.1 više nisu podržane PHP grane. Trenutno podržane grane su navedene na zvaničnoj PHP stranici; za planiranje nadogradnje razumno je testirati 8.4 ili 8.5.
Status: produkcijska verzija nije poznata. Prolazak testova na 7.4 ne zamjenjuje provjeru na produkcijskom PHP-u i MySQL-u.
Ispravka: uskladiti razvoj, CI i produkciju s podržanom verzijom; provjeriti ekstenzije i ponoviti testove nakon nadogradnje. Ne instalirati novu verziju bez odvojenog plana migracije.

F30 — P2 — K / dokumentovano odgođeno — Email identitet se ne potvrđuje
Lokacije: api.php:2389–2449, 2482–2529; DEPLOYMENT.md završna napomena.
Registracija automatski aktivira račun na osnovu sintaktički validnog emaila. Promjena emaila traži trenutnu lozinku, ali ne potvrđuje pristup novom sandučetu niti šalje obavijest starom. SMTP i verifikacija su eksplicitno odgođeni u dokumentaciji.
Uticaj: osoba može zauzeti tuđi email i slati upite pod tom adresom. To ne daje pristup već postojećem tuđem računu ili pošti; takav pristup nije potvrđen. Korisnik nema ni dovršen samostalni oporavak zaboravljene lozinke.
Ispravka: pending email/verifikacijski token s rokom i jednokratnom upotrebom; odgovarajući limiti, potvrda nove adrese i obavijest o promjeni. Do implementacije email jasno tretirati kao neprovjeren kontakt i ne dodavati ručni nesigurni password-reset zaobilazni put.

F31 — P3 — K — Zajednički CSS se učitava pod različitim verzijama nakon izmjene
Lokacije: admin.html:11, login.html:11, profile.html:11 nasuprot cart.html:28, product.html:40, blog.html:14; .htaccess ExpiresByType text/css.
admin.css je lokalno promijenjen i tri stranice koriste novu oznaku 20260905-auth-2, dok druge tri zadržavaju 20260903-ui-1. Cache za CSS traje 30 dana. Postojeći posjetilac može na različitim stranicama koristiti različit sadržaj istog CSS-a.
Status: potvrđene reference i cache pravilo; nije simuliran stvarni stari Cloudflare/browser cache. Novi browser u testovima učitava trenutni fajl pa ne pokriva ovaj rizik.
Ispravka: jedinstven build/content hash za sve reference promijenjenog zajedničkog resursa; pri deployu provjeriti navigaciju sa već popunjenim cacheom.

F32 — P2 preventivno — U/K — Deployment artefakti i IIS zaštita nisu jednako ograničeni
Lokacije: .htaccess:28–35; web.config; korijenski ones-*.zip i deployment-* direktoriji.
U radnom web rootu nalaze se ZIP paketi i stare deployment kopije. Root Apache pravila blokiraju deploy/ i tests/, ali ne sve deployment-* direktorije ili *.zip fajlove. ZIP pregled nije pokazao config.local.php, SQLite ili backup JSON unutar pregledanih arhiva; one ipak sadrže izvorni kod/stare verzije. IIS web.config ima uži skup zabrana od Apache pravila i nije ekvivalentna zaštita za sve JSON backup/razvojne putanje.
Produkcijska provjera: poznati /ones-deployment-ready.zip je 404; privatne testirane putanje su 403. Nema dokaza da su arhive ili stare kopije trenutno izložene.
Ispravka: javni document root treba sadržati samo dozvoljene runtime fajlove; zadržati postojeći allowlist deploy/build-package.ps1 tok. Arhive/staging izvana web root-a ili eksplicitno zabranjene. Za IIS definisati i testirati ekvivalentne zabrane ako se taj hosting stvarno podržava; inače jasno navesti Apache kao podržani produkcijski target.
