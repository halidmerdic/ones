T16 — TIPOVI CMS KOLEKCIJA
Redovni HTTP save čuva razliku JSON objekta i liste prije pretvaranja u PHP
asocijativne nizove. Svih deset kolekcija, galerije proizvoda, atributi kategorija
i njihove vrijednosti moraju biti liste sa uzastopnim indeksima. JSON objekat
sa ključem "0" također je odbijen, čak i kada bi ga PHP dekodirao kao listu.
Zapisi i mape imaju odvojena pravila; ugniježđeni objekti u skalarnim poljima
ne dolaze do pretvaranja u string. Greška vraća HTTP 422 i putanju polja, bez
promjene CMS-a, njegove revizije ili historije.

PHP save_cms također poziva punu validaciju, tako da je ne mogu preskočiti
interni pozivi. Prazne specs/attributes mape u API odgovoru su {}. Browser ih
uređuje kao objekte: imenovani atribut više ne nestaje pri JSON.stringify
praznog PHP niza koji se ranije prenosio kao []. Stare prazne mape [] ostaju
prihvatljive radi kompatibilnosti. Stare imenovane kolekcije se pri čitanju
reindeksiraju bez odbacivanja zapisa i bez automatskog upisa u bazu.

T17 — DOSLJEDNOST REFERENCI
Novi save zahtijeva tačne reference: product.category/badge, category.badge,
badge.applyCategory i manual.relatedProductId/category. Nepostojeća referenca
ili drugačija slova/okolni razmaci više ne mogu proći validaciju pa nestati u
javnom prikazu. Izabran je tačan zapis referenci, bez migracije naziva u nove ID-eve.

Pri čitanju postojećih podataka i uvozu backupa, stara referenca se može razriješiti
na stvarni zapis samo ako je podudaranje po trim/lowercase jedinstveno. Nepoznate
ili dvosmislene veze se ne nagađaju. Nazivi entiteta i sami ID-evi se ne mijenjaju.
Isto pravilo čitanja koristi sitemap. Uspješan sljedeći save trajno zapiše tačne
reference; samo čitanje ne mijenja bazu. Backup zadržava punu validaciju i rollback.

T18 — NEPROMJENJIVI ID PROIZVODA
Postojeći ID više nije ulaz za preimenovanje u editoru. Polje je readonly,
dostupno za čitanje/kopiranje i ima objašnjenje povezano za čitače ekrana.
Naziv se normalno mijenja. Novi proizvod dobija product-UUID identifikator.

Admin CMS odgovor nosi _identity dokaz izveden iz ID-a i privatnog auth_epoch
ključa pomoću HMAC-SHA256. Postojeći proizvod mora ga vratiti neizmijenjenog.
Promijenjen ID sa starim dokazom, neispravan dokaz ili postojeći ID bez dokaza
odbijaju se i kada se zaobilazi editor. Novi proizvod nema dokaz prije prvog
spremanja. Polje se uklanja prije upisa i ne ulazi u javni CMS niti backup.

Spremanje zahtijeva reviziju i provjerava identitete pod zaključavanjem CMS reda;
SQLite uzima write lock prije čitanja, a MySQL koristi SELECT FOR UPDATE.
Samo jedan konkurentni save iste revizije prolazi. Odbijeni zahtjev otpušta svoju
transakciju. Restore mijenja auth_epoch; stari dokazi više ne važe.

Admin pamti prethodno spremljene ID-eve i šalje izričitu deletedProductIds listu.
Nestanak postojećeg ID-a bez takve liste ne tretira se kao legitimno brisanje.
Ovo je ugovor za uređivanje i zaštita od nenamjernog preimenovanja, uz postojeću
admin autorizaciju. Namjerno brisanje i stvaranje novog zapisa su odvojene radnje;
ovaj mehanizam ne tvrdi da ih privilegovani administrator ne smije izvršiti.
Restore/reset ostaju posebne operacije zamjene cijelog snimka. Potpuno rješavanje
zavisnosti pri brisanju proizvoda/kategorija/oznaka ostaje za T19–T21.

T39 — BROJ U NAZIVU RUŠI SITEMAP
Smoke test sa stvarno spremljenim nazivom "Naziv 1440 true" otkrio je PHP
TypeError u strpos. PHP pretvara numerički ključ riječi u integer, dok strict
strpos zahtijeva string. Oba mjesta koja čitaju ključ sada eksplicitno koriste
tekst. Numerički naziv, numerička riječ prije/poslije teksta, nepodudaranje i
proširenje ključne riječi romobil/skuter imaju poseban regresijski test.
Ovim nije promijenjena postojeća politika filtera blogova, koja ostaje T26.
