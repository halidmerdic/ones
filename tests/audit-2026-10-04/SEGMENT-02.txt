T04 — DEMONSTRACIJSKI ADMIN
Server prepoznaje hash poznate demo lozinke i placeholdera iz konfiguracije.
Centralni require_admin blokira sve privatne admin radnje dok se lozinka ne
promijeni, uključujući postojeće sesije. Jedini izuzetak je promjena lozinke;
status i odjava ostaju dostupni. CMS interfejs nudi samo sigurnosnu formu i
odjavu, čak i uz URL koji direktno traži proizvod ili drugi panel.
Produkcija odbija prijavu demo lozinkom. Vlasnik može otvoriti ograničenu sesiju
samo privatnom jakom initial_admin_password lozinkom iz serverske konfiguracije.
Nema tihog reseta hashova. Ta vrijednost nikada ne zaobilazi postojeću sigurnu
admin lozinku. Rehash pri prijavi ne pretvara recovery lozinku u stalnu.
Promjena lozinke povećava auth_version i poništava ostale sesije.
Produkcijski JSON restore odbija demo admina prije pisanja. Lokalno je moguća
migracija starog demo backupa uz obaveznu promjenu lozinke.
Operativna procedura je zapisana u DEPLOYMENT.md i komentaru config.example.php.

T05 — POTVRĐENA ODJAVA
Početna, proizvod, blog i profil koriste zajednički onesLogoutCustomer.
Nakon greške POST-a provjerava se svjež customer-status. Samo potvrđena odjava
smije obrisati lokalni prikaz identiteta/korpe i prikazati uspjeh. Ako se potvrda
ne može dobiti, prikaz prijave ostaje i dugme omogućava ponovni pokušaj.
Izgubljen odgovor nakon već izvršene odjave se pravilno prepoznaje.
Paralelni klikovi dijele jedan zahtjev; na profilu se blokiraju desktop i mobilno
dugme. Nedostupna lokalna pohrana ne smije poništiti potvrđenu odjavu.
Ostali problemi dostupnosti browser storage-a ostaju pod T29.

T06 — ŽIVOTNI CIKLUS SLANJA KORPE
finally je premješten iz loadCart u submitOrder, gdje postoje odgovarajuće
varijable. Svaki završetak vraća naziv dugmeta i orderSubmitting stanje.
Jedno mjesto upravlja kontrolama prema stanju učitavanja, izmjene, slanja,
prazne korpe i nedostupnih proizvoda. Slanje i promjene količine/brisanje se
međusobno blokiraju unutar te stranice; to ne zamjenjuje T14 za više tabova.
Telefon i napomena se zaključavaju tokom slanja. Nakon neuspjeha unos ostaje;
nakon uspjeha briše se napomena. API greške nose HTTP status, pa 401 vodi na
prijavu. Povratak iz prijave u korpu ostaje odvojeni T28.
Ako se odgovor izgubi, osvježi se korpa i traži provjera upita na profilu.
Zahtjev se ne šalje automatski ponovo. Time je pokriven slučaj kada je server
već sačuvao upit, a browser nije primio uspješan odgovor.
Promijenjeni script URL-ovi imaju verziju 20261005-security-2.
